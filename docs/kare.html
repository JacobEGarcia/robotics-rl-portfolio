1 — Convincing with Evidence

A simulator that has
never been wrong
is not a simulator

The DROID dataset records two things most robot logs blur together: what the controller was commanded to do, and where the arm actually went. They are never the same. Real joints carry friction, rotor inertia, finite stiffness, and delay.

So: replay the real commands open-loop through a simulated Panda, measure how far it drifts from the real arm, and fit the simulator until the drift shrinks. The simulator starts from the robot's first measured state and never sees ground truth again.

Parameters were fitted on 24 episodes and scored on 8 the optimiser never touched. The split is by episode, never by frame — frames inside one trajectory are correlated, and a frame-level split leaks the answer.

The identified values are more interesting than the error. Menagerie ships the Panda with zero dry friction and zero latency. The data disagrees with both: friction rises from nothing to 3.07, and latency lands at 3.3 steps — about 220 milliseconds at 15 Hz.

THE FIRST DATASET HAD NO ANSWER IN IT

An earlier attempt used a different Franka dataset. Its action column turned out to be exactly state[t+1] − state[t] — correlation 1.0000 on every joint.

The "commands" were relabelled state differences. Nothing in that dataset was ever measured independently, so fitting a simulator to it would have produced a perfect, meaningless result. A perfect fit is usually evidence of a broken measurement.

2 — Convincing with Constraints

Tendons do not
behave like joints

A tendon pulls but never pushes, so every joint needs an antagonist. It routes over curved surfaces, so its leverage changes with angle. And it drags — so the joint arrives somewhere different depending on which direction it came from.

AT ZERO FRICTION, THE LOOP SHOULD CLOSE. IT DOESN'T.

There is still 0.207 rad of hysteresis with friction set to zero, which should be impossible. The finger jumps to a flexed pose at 2.05 N going up, but does not fall back until 1.03 N coming down. It is bistable.

One tendon spans both joints, so they cannot be commanded independently. Friction hysteresis can be compensated. Bistability cannot — it is built into the kinematics.

3 — Convincing with Fundamentals

Two algorithms,
written by hand,
on purpose

PPO and SAC, roughly three hundred lines each, no reinforcement-learning library. Both solve the same task. The interesting number is not either one — it is the distance between them.

That 9.41× gap is an engineering argument. On a physical robot every step costs time and actuator wear, so sample efficiency wins. In a massively parallel simulator samples are nearly free and throughput wins instead.

4 — Convincing with Speed

The same algorithm,
28x faster, on the
same processor

The PyTorch version is a loop with the Python interpreter inside it, once per environment step. The JAX version compiles the whole rollout into a scan and vectorises five hundred environments at once. Nothing interpreted remains in the hot path.

THE PORT REPRODUCED THE ORIGINAL'S BUG, EXACTLY

The first JAX version ran at 196,000 steps per second and learned nothing at all — flat at −1200, the same symptom the PyTorch version had shown, from the same cause: no reward scaling.

Two independent implementations failing identically is not embarrassing. It is evidence the two agree.

5 — Convincing with Honesty

Seven bugs, none of
which raised an
exception

Every result here was checked against something outside itself — a published baseline, a second implementation, a physical consistency requirement, or data the optimiser never saw. None of the following announced itself. Each produced running code and plausible output.

MISSING REWARD SCALING — PYTORCH

Value loss ~10⁶ against a policy loss of ~10⁻². Gradient clipping handed almost everything to the critic. The policy was starved, not broken.

MISSING REWARD SCALING — JAX

The same bug, found again independently in a different framework.

TENDON SIGN CONVENTION

Routing sets the moment arm's sign, gear sets the force's, and the product decides direction. Two attempts each got one half right.

A SINUSOID THAT WASN'T QUASI-STATIC

Measured phase lag rather than friction, reporting hysteresis that fell as friction rose. Exactly backwards.

WRAP GEOMS LEFT COLLIDABLE

~18% phantom hysteresis. Found only because a second physics backend refuses cylinder-box collisions and failed loudly where the first was silent.

TRUNCATION BOOTSTRAP UNDER AUTORESET

In a vectorised rollout the next step's value belongs to a different trajectory.

A DATASET WITH NO REALITY GAP

Commanded and measured were the same signal, one step apart.

REPRODUCIBILITY

Every run writes one append-only log whose first line is a manifest: seed, configuration, git commit, library versions, and a hash of the compiled physics model. Hashing the compiled model catches edits the source alone would hide, so any figure traces to the exact physics that made it. Those logs are committed.

Colophon

On the drawing. The seven icons here are 32×32 grids, authored as literal character maps — # for ink, . for paper — and rendered with nearest-neighbour scaling only. Susan Kare drew hers on graph paper with a pink marker, 1,024 squares at a time, working to a stated standard of simplicity, clarity, and beauty.

On the photographs. Every plate is reduced to one bit per pixel using Atkinson dithering, written by Bill Atkinson for the same machine. It discards a quarter of the quantisation error rather than diffusing all of it, which is why early Macintosh images have their particular hard, sparkling look.

On the type. The interface is set in Silkscreen, standing in for Chicago — Kare's bitmap system face, which is Apple's. Documents are set in a smooth face, following the original Macintosh's own division: a bitmap face for the interface, a readable one for the writing.

On the source. Reference: Theresa Günther, How To Become Successful — Learning From Susan Kare, Muthesius University of Fine Arts and Design, 2020.
